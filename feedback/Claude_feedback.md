# ACR-AC-RAG: Competitive Review & Developer Action Items

**Project:** `acr-ac-rag` — FHIR-native Clinical Decision Support Hub  
**Purpose of this document:** Competitive landscape analysis vs. official ACR/PAMA/CareSelect ecosystem + prioritized issues requiring code or architecture changes.

---

## 1. Context — What the Official ACR Ecosystem Actually Does

Understanding this prevents over-engineering to compete where competition isn't needed.

The ACR publishes the **Appropriateness Criteria** as content only. The official CMS-qualified Clinical Decision Support Mechanism (qCDSM) is **CareSelect® Imaging**, operated by Optum. Its core functionality is:

- Accepts **structured EHR inputs** (ICD-10 codes, CPT order codes) — **not** free text
- Returns an **appropriateness score of 1–9** based on matched AUC criteria
- Attaches consultation data to the downstream Medicare claim for **PAMA billing compliance**
- Provides analytics dashboards on provider ordering patterns
- Includes content from ACR, ACC (cardiology), NCCN (oncology), and SNMMI (nuclear medicine)

**What CareSelect does not do:**
- Parse unstructured clinical notes
- Evaluate contrast safety (eGFR, allergy, nephrotoxicity)
- Flag pregnancy + radiation risk
- Manage anticoagulant holds for IR procedures
- Re-route queries when contraindications are detected
- Protocol a scan (contrast type, volume, phase sequences)
- Offer any conversational/co-pilot interface

**Conclusion:** This system and CareSelect solve different problems. Do **not** position `acr-ac-rag` as a PAMA qCDSM replacement — that requires multi-year CMS certification. Position it as the **clinical intelligence layer** that operates alongside compliance tools.

## 2. System Strengths — Do Not Break These

The following are genuine differentiators. Changes in these areas require careful regression testing.

| Capability | Why It Matters |
|---|---|
| **NLP → FHIR pipeline** (`fhir_converter.py`) | No commercial qCDSM accepts free-text input. This is a core moat. |
| **Safety engine** (`safety_engine.py`) | eGFR/contrast alerts, allergy cross-reactivity (RxNorm/SNOMED), pregnancy + radiation, metformin holds, IR anticoagulant holds with INR/platelet thresholds. Nothing like this exists in any qCDSM. |
| **Closed-loop contraindication re-routing** (`rag_engine.py`) | On severe contraindication (e.g. pacemaker + MRI), the engine re-queries constrained to safe alternatives. CareSelect just shows a score and stops. |
| **Protocoling assistant** (`protocol_mapper.py` + `protocol_db.py`) | Takes recommendations from "what to order" to "how to scan it" — contrast parameters, phase sequences, localized hospital protocols. No commercial CDS system does this. |
| **Confidence-based review queue** (`main.py`, `data/query_cache.db`) | Queries below 0.55 routed to human review. Important for safe deployment. |
| **Tiered LLM routing** (`llm_router.py`) | Flash-lite for helpers, Flash for complex tasks — keeps Cloud Run costs low. |

## 3. Action Items — Issues Requiring Code or Architecture Changes

Issues are ordered by clinical risk, not implementation effort.

---

### 🔴 PRIORITY 1 — Clinical Safety / Legal Risk

#### 3.1 Reframe the "Attending Radiologist" Persona

**Problem:** The `copilot_engine.py` conversational drawer is framed as an "Attending Radiologist." If an LLM hallucinates a recommendation under this label, it creates a clinical liability vector and misrepresents what the system is.

**Action items:**
- Rename the persona in the UI and system prompt. Suggested: `"Guideline Assistant"`, `"ACR Reference Assistant"`, or `"Protocol Co-Pilot"`.
- Add a persistent, visible disclaimer to every co-pilot response. Suggested text:

  > *This output is generated by an AI system referencing published ACR Appropriateness Criteria. It does not constitute clinical advice and does not substitute for physician judgment. Always verify recommendations against current guidelines and patient context.*

- Add the disclaimer as a suffix injected in `copilot_engine.py` at the response-generation level, not just in the UI, so it persists in any downstream integration.

---

#### 3.2 HIPAA / PHI Exposure in Cloud API Calls

**Problem:** `fhir_converter.py` sends clinical text to the Gemini API. If a real clinician pastes a real patient note into the dashboard, that is PHI being transmitted to a third-party API without documented HIPAA safeguards.

**Action items:**
- Confirm a **Business Associate Agreement (BAA) is in place with Google Cloud** for the GCP project hosting this service. Document this in the README under a `## Compliance` section.
- Add a visible warning to `index.html` on the query input field: *"Do not enter real patient identifiers. For simulation and research use only."*
- Consider adding a pre-processing step in `fhir_converter.py` that strips obvious PHI patterns (MRN formats, SSN patterns, DOB in specific formats) before the payload is sent to the Gemini API, as a defense-in-depth measure.
- In `security_utils.py`, extend the existing prompt-injection pattern matching to also flag and redact common PHI patterns before API transmission.

---

### 🟠 PRIORITY 2 — Data Integrity / Accuracy Risk

#### 3.3 Guideline Currency — Automated Update Pipeline

**Problem:** The system indexes 275 ACR Appropriateness Criteria PDFs. The ACR updates these guidelines annually. There is currently no documented mechanism to detect, pull, and re-ingest updated PDFs. Stale guidelines produce stale (and potentially incorrect) recommendations.

**Action items:**
- Create a scheduled Cloud Run Job (or GitHub Actions workflow) that runs monthly and:
  1. Checks the ACR website or a configured manifest for PDF version/date changes.
  2. If changes are detected, re-runs `ingest.py` against updated source files.
  3. Runs the self-healing `init_procedures_db()` row-count check against the refreshed data.
  4. Uploads updated `chroma_db_gemini` and `acr_procedures.db` to the GCS bucket.
- Add a `data/guideline_manifest.json` file tracking the version, date, and hash of each ingested PDF so drift is detectable.
- Display the guideline dataset version date prominently in the `index.html` dashboard header so users know how current the data is.

---

#### 3.4 RAG Accuracy — Validation Benchmark Missing

**Problem:** There is no documented benchmark for retrieval accuracy. The system's false-negative rate (missing a guideline match that should have been found) and false-positive rate (returning an inappropriate recommendation confidently) are unknown.

**Action items:**
- Build a test fixture in `test_all_upgrades.py` (or a new `test_rag_accuracy.py`) with at least 30–50 hand-curated clinical scenarios with known correct ACR guideline mappings and expected appropriateness ratings.
- Run this benchmark against the live RAG pipeline and record precision/recall at the current confidence threshold of 0.55.
- Add this benchmark to the CI/CD GitHub Actions workflow so regressions are caught before deployment to `main`.
- Document baseline accuracy metrics in the README under a `## Accuracy & Validation` section.

---

### 🟡 PRIORITY 3 — Scope Gaps vs. Commercial Alternatives

#### 3.5 Single-Society Content (ACR Only)

**Problem:** CareSelect bundles ACC (cardiology), NCCN (oncology), and SNMMI (nuclear medicine) AUC alongside ACR. A cardiologist ordering a nuclear stress test needs ACC guidance. This system only covers ACR.

**Action items:**
- Evaluate whether ACC and SNMMI publish machine-readable or PDF guideline content that can be ingested via `ingest.py`.
- If ingesting additional societies: update `rag_engine.py` to tag retrieved chunks by source society (`"source_society": "ACC"`) and surface this in the response so users know which body's criteria were applied.
- In the interim, add a disclaimer to the `index.html` UI: *"This system references ACR Appropriateness Criteria only. For cardiology (ACC) or nuclear medicine (SNMMI) imaging, consult the relevant society guidelines."*

---

#### 3.6 PAMA Compliance Gap — Clear User Communication

**Problem:** The system generates a DSN audit token (`ACR-[DATE]-[HASH]`) which may be confused with a CMS-compliant Decision Support Number (as required for Medicare billing under PAMA). This system is **not** a CMS-qualified CDSM and cannot be used for PAMA billing compliance.

**Action items:**
- Rename the internal audit token to avoid confusion. Suggested: `INTERNAL-AUDIT-[DATE]-[HASH]` or `ACR-AC-RAG-[DATE]-[HASH]`.
- Add a comment in `main.py` near the DSN generation logic:
  ```python
  # NOTE: This is an internal audit identifier for logging/compliance tracing only.
  # It is NOT a CMS-qualified Decision Support Number (DSN) for PAMA Medicare billing.
  # For PAMA qCDSM compliance, a CMS-certified mechanism (e.g. CareSelect) is required.
  ```
- Update the README and dashboard UI to make this distinction explicit.

### 🔵 PRIORITY 4 — Operational / DevOps

#### 3.7 GCS Bucket Path Exposed in README

**Problem:** `README.md` contains the literal GCS bucket path `gs://acr-ac-rag-data-667793722294/...`. If the repo is public, this exposes infrastructure details.

**Action items:**
- Replace hardcoded bucket paths in the README with an environment variable reference: `gs://$GCS_BUCKET_NAME/...`
- Add `GCS_BUCKET_NAME` to the `.env` template in the README.
- Verify the bucket has appropriate IAM permissions (not publicly readable).

---

#### 3.8 SQLite WAL Files on Cloud Run — Persistence Caveat

**Problem:** The system copies SQLite DBs from GCS to `/tmp` on container startup for RAM-speed access. Cloud Run instances are ephemeral — any writes to `/tmp` (override logs, review queue entries, query cache updates) are lost when a container instance is recycled unless they are synced back to GCS.

**Action items:**
- Audit which SQLite databases are **write-heavy** at runtime:
  - `query_cache.db` — writes on every cached query
  - `query_cache.db` (review queue) — writes on low-confidence queries
  - Override database — writes on clinician overrides
- Implement a GCS sync-back on write for these databases, or use a dedicated async background task that periodically flushes `/tmp` writes back to GCS.
- The `dsn_audit_log.jsonl` should be written directly to GCS (via a streaming write or periodic flush) rather than local `/tmp` to ensure audit trail durability across instance recycling.

## 4. Recommended Positioning (Non-Code, but Informs Architecture Decisions)

This system's strongest use cases, in order of deployability:

1. **Radiology department protocoling assistant** — Residents and techs use it to confirm scan protocols against ACR criteria. No PHI, no PAMA compliance required.
2. **Clinical safety screening tool** — Contrast contraindication checking, IR pre-procedure checklist. The safety engine is the highest-value unique feature.
3. **Medical education / simulation** — Teaching appropriate imaging ordering in academic settings.
4. **Quality improvement research** — Analyzing ordering patterns against ACR criteria in a research context with de-identified data.

**Do not position as:** a PAMA qCDSM replacement, a billing compliance tool, or a standalone clinical decision-making system without physician oversight.
